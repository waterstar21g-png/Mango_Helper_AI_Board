## 반영 내용

### 1. 미매핑 절대 금지 재확인 (원문 1)

기존에 이미 확정된 절대규칙("미매칭 상태로 망고에 정보를 전달하지 않는다
— 반드시 최종 카테고리를 매핑할 것", `find_category` 의 6) 근접매핑
강제지정 및 `keyword_dictionary` 의 5) 최근접 강제지정)을 재확인했다.
별도 코드 변경 없음 — 이미 그렇게 구현돼 있음을 재확인.

### 2. 연관검색어DB(keyword_dictionary) 실제 실행 경로 연결 (원문 2)

지적대로 `keyword_dictionary.KeywordDB` 가 자체 테스트에서만 쓰이고
실제 매핑 실행 경로(`map_categories.py`)에는 한 번도 연결되지 않았다.

| 변경 | 내용 |
|------|------|
| `matching.find_category(..., keyword_db=None)` | 5) 단계에서 `category_db` 와 함께 `keyword_db.resolve()` 로도 검색어를 확장한다 |
| `map_categories.build_keyword_db(excels)` | 신설 — 전체 엑셀로 `KeywordDB` 구축 |
| `best_category`·`best_category_with_step`·`map_one_market`·`_map_once`·`map_one_row`·`run_mapping`·`run_dry` | 전부 `keyword_db` 매개변수를 추가해 실제로 스레딩 |

### 3. ★실사례 버그 수정 — "정식 분류" 우선 매칭 (원문 3)

"아름트리-무신사-여성-상의-반소매 티셔츠" 필터를 실제 6개 마켓 엑셀
데이터(로컬 `data/market_categories_cache.json`)로 재현해 원인을 찾았다.

- **원인**: AUC20 마켓에 정확한 "반소매" 표기가 없어 근사 매칭 단계로
  넘어갔는데, 여러 "여성" · "티셔츠"류 후보가 동점(hits=4)이 되고,
  최종 동점 처리(짧은 경로 우선)가 우연히 **"여성의류 > 마담의류 >
  티셔츠"**(무관한 이름의 중위 아래 우연히 걸린 리프)를 골랐다. 정작
  검색어("티셔츠") 자체가 중위명인 **"여성의류 > 티셔츠 >
  라운드넥티셔츠"**(이 품목의 정식 분류)는 경로가 조금 더 길다는
  이유로 밀렸다.
- **수정**: `matching._matches_canonical_group()` 신설 — 검색어(하위)가
  리프가 아니라 그보다 상위 단계 이름 **자체**와 일치하면
  `priority_rank` 에 가산점(+6)을 준다. 방향은 "검색어가 그 레벨명에
  포함" 쪽만 인정한다(반대 방향까지 허용하면 "셔츠"(레벨)가 "티셔츠"
  (검색어)의 부분 문자열이라는 이유만으로 부당하게 우대되는 사고가
  재발한다 — 실제로 이 방향 오류 때문에 GMK20 에서 "체크셔츠"가 잘못
  우선되는 것도 함께 발견해 고쳤다).
- **검증(실제 6개 마켓 데이터)**: 수정 후 6개 마켓 모두 "여성 …
  티셔츠" 계열의 적절한 카테고리를 반환한다 — AUC20/GMK20 "여성의류 >
  티셔츠 > 폴라티셔츠", 11ST "여성티셔츠 > 기본티셔츠", COUP "여성의류
  > 티셔츠 > 여성 반소매"(정확 일치), SMART "여성의류 > 티셔츠",
  LTON "티셔츠/맨투맨 > 폴라티셔츠".
