## 반영 내용

### 1. 순서 (요건 그대로 · 변경 없음)

수집조건수정 → 팝업창 → 번역조건 리스트 반영 → 저장하기 → 닫기 → 다음 행.
테스트로 순서를 고정했다 (`test_close_button_is_clicked_right_after_save` —
select 인덱스 < save 인덱스 < close 인덱스).

### 2. 닫기 버튼 (원문 1-2)

스크린샷 DOM 그대로 잡는다.

```html
<a onclick="window.close();" class="defbtn_lar dtype6"><span>닫기</span></a>
```

선택자 순서: `a[onclick*="window.close"]` → `a.defbtn_lar.dtype6` →
`span` 텍스트 `닫기` → 텍스트 포함 요소. 전부 실패 시 `window.close()` 직접 호출,
그래도 창이 남으면 강제 종료. 저장 알림(alert)은 dialog 핸들러가 자동 확인한다.

### 3. 속도 (원문 1-1 · 1-3)

고정 `sleep` 을 걷어내고 대기값을 한 곳(`T_*` · `GAP_*`)에 모아 10배 축소했다.

| 항목 | 이전 | 현재 |
|------|------|------|
| 버튼 클릭 | 3~5초 | **1.5초** |
| 드롭다운 등장 | 15초 | **2초** |
| 현재값 읽기 | 0.4~0.8초 | **0.2초** |
| 팝업 닫힘 | 10초 | **0.8초** (뒤 강제 종료) |
| 검색 후 정착 | 1.0초 | **0.15초** |
| 행 간 간격 | 0.3초 | **0.02초** |
| 팝업 열기 | 8초 | **5초** |

추가로 목록 접속을 **URL 직접 이동(빠른 경로)** 로 먼저 시도한다. 실행로그에서 접속에
9초가 걸린 구간(P3 단계별 절차)을 건너뛰고, 실패할 때만 기존 절차로 폴백한다.

행 처리 자체가 목록 페이지를 떠나지 않으므로(팝업만 사용) 행마다 목록 재로딩이
없다 — 이게 가장 큰 속도 요인이다.
