## 반영 내용

### 1. CSV 원본 저장 (원문 2)

업로드된 두 CSV(CP949/EUC-KR 인코딩)를 UTF-8로 변환해 그대로
`data/category_master.csv`(17,591행)·`data/keyword_dictionary.csv`
(25,399행)로 저장했다. 참조 무결성(Parent_ID·Target_Cat_ID 전부 존재)을
확인했다.

### 2. 신설 `category_master_db.py` — CSV를 그대로 DB화 (원문 1·3-1·3-3)

| 구성 | 내용 |
|------|------|
| `CategoryNode`/`KeywordEntry` | CSV 컬럼(Market 포함) 그대로 보관 |
| `MasterDB.from_csv()` | 두 CSV를 읽어 마켓별 카테고리 트리(Parent_ID 색인) + 검색어 사전 구축 |
| `MasterDB.save_json()`/`load_json()` | ★요건: "GitHub에 올려서 메모리로 보관해 속도를 높이도록" — `data/category_master_db.json`(5.9MB) 단일 캐시로 저장·재사용. CSV 재파싱(0.12초) 대신 JSON 로드(0.07~0.08초)로 매번 시작 |
| `resolve_ranked()` | 기획서의 4단계(완전일치→유사어→동일/연관어→확대범주)를 CSV의 실제 컬럼(Priority 1=EX·2=SY·3=MO, Parent_ID 체인)으로 그대로 구현. 여러 순위 후보를 반환해 절대규칙으로 앞 후보를 건너뛰어도 계속 시도 가능 |

### 3. `map_categories.py` 전체에 1순위로 연결 (원문 3-2)

`best_category_via_master()` 를 신설해 `_map_once`·`map_one_market`·
`map_one_row`·`run_mapping`·`run_dry` 전체에 연결했다. 마스터DB에서
확실한 매칭(1~3단계)을 찾으면 그 즉시 확정하고, 없을 때만(또는 마스터DB
자체가 없을 때만) 기존 `matching.py` 캐스케이드(`category_db`·
`keyword_dictionary`)로 넘어간다. 절대규칙(성별 반대·브랜드)은 마스터DB
결과에도 그대로 적용하며, 이 규칙을 지키는 후보가 정말 하나도 없을
때만 "미검출"로 두어 다음 단계로 넘어가게 한다(오매핑보다 미매핑이
낫다는 절대규칙이 "미검출 절대 금지"보다 우선).

### 4. 실사례 감사로 발견한 버그 2건 수정

실제 CSV로 5개 필터명 × 6개 마켓을 검증하다가 발견한 문제를 즉시 고쳤다.

- `_is_non_product_hint` 가 리프만 보아 "건강/의료용품 > 실버용품 >
  휠체어 악세서리"("건강"이 최상위에만 있음)를 놓쳤다 — 경로 전체를
  보도록 수정.
- `GENDER_WORDS` 에 "남아"·"여아"가 없어 "여성-신발-구두" 검색이
  "남아구두"(남자아이)로 새는 사고 — 성별 판정에 추가.
- 검색어와 후보의 품목 계열이 다르면("목걸이" 액세서리 ↔ "목걸이 지갑"
  가방) 대안이 있는 한 피하도록 소프트 규칙 추가.
