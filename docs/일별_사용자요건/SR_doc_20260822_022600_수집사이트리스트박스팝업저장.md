## 반영 내용

### 1. 수집사이트 리스트박스 (원문 1)

스크린샷의 `<select name="site_id" class="input_" style="width:160px">` 를 기준으로,
보드 입력에 **리스트박스 2개**(수집사이트 · 번역옵션)를 뒀다. 수집사이트 기본 목록은
스크린샷 순서 그대로다.

```
-- 수집사이트 --   (전체)
4910.kr
ABCmart.a-rt.com
HIVER.co.kr
MUSINSA.com
Zara.com/de
```

전체가 아니면 목록 화면에서 그 사이트를 선택하고 **검색을 실행**한 뒤(검색줄
`span.bt_type` 버튼, 실패 시 `input[name="sch_keyword"]` Enter) 결과 행만 처리한다.
`[망고에서 옵션 읽기]` 는 이제 수집사이트·번역옵션 두 목록을 함께 읽어
`.site_options.json` · `.translate_options.json` 에 캐시한다
(출력 규약 `##SITE##` · `##OPTION##`).

### 2. 팝업 저장 흐름으로 재구현 (원문 2)

스크린샷에서 확인한 실제 구조에 맞춰 행 처리 로직을 바꿨다.

| 단계 | 근거 (스크린샷 DOM) |
|------|--------------------|
| 수집조건수정 클릭 | `<a onclick="modify_filter('720');" class="defbtn_sm dtype6"><span>수집조건수정</span></a>` |
| 팝업창 열림 | `admin_group_modify.php?ps_mode=modify_filter&ps_fuid=720` (별도 창) |
| 번역 후 저장 선택 | 팝업 내 `select[name="translate_method"]` |
| 저장하기 | `<a onclick="set_save();" class="defbtn_lar dtype2"><span>저장하기</span></a>` |
| 모달 닫기 | `window.close()` — 닫힘 이벤트 대기, 안 닫히면 직접 닫음 |

- 저장 알림(alert)은 `dialog` 핸들러로 자동 확인
- **목록 페이지를 떠나지 않는다** → 수집사이트 검색조건이 풀리지 않는다
  (이전 구현은 행마다 목록 URL 로 복귀해 조건이 초기화됐다)
- 폴백 2개: 팝업 클릭이 막히면 팝업 URL 을 직접 열고, `[저장하기]` 요소를 못 찾으면
  `set_save()` 를 직접 호출

이전 구현에서 쓰던 `P3_필터_갱신` 의 수정화면 진입·저장·확인 경로는 이 흐름에
맞지 않아 사용을 끊었다 (행 목록 읽기 `list_demango_rows` 만 계속 사용).

### 3. 첫 화면 URL (원문 3)
