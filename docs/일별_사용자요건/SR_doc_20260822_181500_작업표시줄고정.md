## 반영 내용

### 원인

고정 기능은 1.6.2 에 이미 들어가 있었지만 실제로는 동작하지 않았다. 원인이 둘이다.

**첫째, 바로가기 타깃이 `run.bat` 이었다.** Windows 는 `.bat`·`.cmd` 를 직접 가리키는
바로가기에 「작업 표시줄에 고정」 verb 를 아예 제공하지 않는다. verb 목록에 없으니
자동 고정은 물론 사용자가 우클릭해도 그 메뉴가 보이지 않는다.

**둘째, 고정 verb 를 문자열 하드코딩으로 찾았다.** `"작업.?표시줄에 고정|Pin to tas"`
패턴으로 대조했는데, 이 문자열은 Windows 언어팩·빌드에 따라 달라진다.

### 수정

| 대상 | 내용 |
|------|------|
| `board/desktop_icon.py` | 바로가기 타깃을 `cmd.exe` 로, `run.bat` 은 인자 `/c "…\run.bat"` 로 |
| `board/desktop_icon.py` | verb 이름을 `shell32.dll` 문자열 리소스 **5386** 에서 읽어 1순위 대조 (기존 패턴은 폴백) |
| `board/desktop_icon.py` | 자동 고정 실패 시 `explorer /select,<아이콘>` 으로 아이콘 선택 상태의 탐색기 창 띄움 |
| `board/desktop_icon.py` | `--pin-only` 신설 — 아이콘 재생성 없이 고정만 |
| `망고보드_작업표시줄고정.bat` | 신설 — `--pin-only` 호출 |
| `README.md` | 고정 방법·제약 반영 |

타깃만 `cmd.exe` 로 바뀌고 인자로 `run.bat` 을 넘기므로, 실행 동작·작업 폴더·아이콘은
이전과 같다. 아이콘은 여전히 **1개만** 만든다.

### 남는 제약 (정확히 밝혀 둠)

Windows 10 1903 이후와 Windows 11 은 스크립트를 통한 작업표시줄 자동 고정을 의도적으로
차단했다. 타깃을 `cmd.exe` 로 바꿔 **메뉴가 나타나게** 만든 것까지가 프로그램이 할 수 있는
일이고, 마지막 클릭은 사용자가 해야 한다. 그래서 실패 시 아이콘을 선택한 탐색기 창을
띄워 우클릭 → [작업 표시줄에 고정] 을 한 번에 누를 수 있게 했다 (Win11 은 [자세히 보기]
안에 있다). 시작 메뉴 등록과 `User Pinned\TaskBar` 폴더 복사도 그대로 유지한다.

억지로 뚫는 방법(`Taskband` 레지스트리 blob 직접 쓰기, 서드파티 `syspin.exe` 동봉)은
Windows 빌드마다 형식이 달라 작업표시줄이 깨질 수 있어 쓰지 않았다.
