## 반영 내용

로그의 오류는 **두 개의 서로 다른 문제**다.

### 문제 1 — 상품수집사이트 선택 실패 (고침)

`select_site` 가 입력값을 옵션과 **정확 일치**로만 찾았다.

```python
loc.select_option(label=site_id)   # 'MUSINSA.COM'
loc.select_option(site_id)         # value 로도 시도
```

화면 옵션은 `MUSINSA.com` 인데 입력은 `MUSINSA.COM` 이라 둘 다 실패했다.
대소문자 하나 차이다.

이제 화면의 옵션 텍스트를 읽어 **정확 → 대소문자·공백 무시 → 부분 포함** 순으로
맞춘다. `P3_필터단위_수집조건수정` 의 `match_option` 과 같은 방식이다.
`match_site_option` · `read_site_options` 를 신설했고, 보정했을 때는
`(입력 MUSINSA.COM → 화면 MUSINSA.com)` 을 로그에 남긴다. 실패하면 화면의 옵션
목록을 그대로 출력한다.

`P5_101` 과 `P3_설정수정_카테고리매핑초기화` 가 같은 함수를 쓰므로 함께 고쳐진다.

### 문제 2 — 작업 대상 행 0건 (원인 확인, 조치는 진단 보강까지)

진단이 `tr=0` · `search_category=False` 다. 표에 행이 없는 게 아니라 **화면에
`<tr>` 자체가 하나도 없다** — 목록 화면이 아닌 빈 페이지를 열었다는 뜻이다.

URL 이 `admin_group.php?pmode=filter_delete&uids=&…` 인데, 이는 `map_categories.py`
의 `DEFAULT_LIST_URL` 기본값이다. `pmode=filter_delete` 에 `uids=` 가 빈 값이라
목록이 렌더링되지 않는다. 함께 주신 DOM 스크린샷에는 `table#search_category` 와
`attr-uid="790"` 행이 정상적으로 보이므로, 화면 자체는 존재하고 **기본 URL 이
그 화면을 가리키지 않는 것**이다.

기본 URL 을 임의로 바꾸는 것은 하지 않았다. 이 프로그램은 되돌릴 수 없는 초기화를
수행하므로, 어떤 목록을 대상으로 삼을지 추측으로 정하면 엉뚱한 행을 지울 수 있다.
대신 원인을 바로 알 수 있게 진단을 보강했다.

| 항목 | 변경 |
|------|------|
| URL 로그 | 80자 절단 제거 — 전체 URL 출력 |
| 표 없음 감지 | `tr=0` 이고 `search_category=False` 면 「작업 URL 이 목록 화면이 맞는지 확인」 안내 |
| 사이트 옵션 | 진단에 화면의 상품수집사이트 옵션 목록 출력 |

### 확인 필요

브라우저에서 검색필터 목록 화면을 띄운 상태의 **주소창 URL** 을 알려주시면
`DEFAULT_LIST_URL` 을 그 값으로 고정한다. 그때까지는 보드 「작업 URL」 칸에 그 URL 을
직접 붙여넣으면 정상 동작한다.
