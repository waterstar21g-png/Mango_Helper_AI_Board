### 1. 신설 `category_db.py` — 통합정보화DB (요건 B)

6개 마켓 엑셀 카테고리를 하위·중위·상위 단계별로 교차색인하고, 검색어에
대한 연관검색어를 하위=1순위·중위=2순위·상위=3순위로 반환한다
(`CategoryDB.build` · `search` · `related` · `related_terms`).

### 2. `matching.py` — 탐색 순서 전면 재작성 (요건 D)

`find_category` 를 요건 D-4(대전제) 순서 그대로 재구성했다.

| 단계 | 동작 |
|------|------|
| 1) 완전일치 | 상위·중위·하위 단계수·이름 전부 일치 |
| 2) 하위검색 | count=1 확정 · count=0→4) · count>1→3) |
| 3) 우선순위 | 상위/중위 일치 OK → 국내(해외 아님) OK → 그래도면 정보화DB |
| 4) 확장범주 | 의류·신발·잡화 등 포괄 카테고리 (요건 11-2·3: 하위 1차 → 중위 2차 → 확장범주) |
| 5) 정보화DB | `db.related_terms()` 로 검색어 확장 후 2)~5) 재시도 (최대 3회) |
| 6) 근접매핑 | 그래도 없으면 소재·용도·성별·활용 종합해 반드시 하나 지정 |

절대규칙(성별 반대·브랜드·엑셀범위)은 그대로 유지했다.

### 3. 우선순위 9가지 (요건 B-9) — `matching.priority_rank`

성별 정확일치 > 중성/혼용/공용, `<성별>의류 > 패션의류 > 패션의류잡화`,
국내 > 해외 를 `pick_best` 선택 시 점수화해 반영. `clothing_priority` 도
성별 인자를 받아 순서를 재구성했다(`clothing_preferred_for`).

### 4. 규칙3 우선순위 반전 — 하위 → 중위 → 상위 (요건 B-8-3, B-11-2·3)

기존(상위→중위→하위)을 정반대로 뒤집었다. `item_paths` 가 품목명이
나오는 단계의 "깊이 비율"로 정렬해 리프(하위)에 가까운 후보를 먼저
고른다.

### 5. 엄격규칙 10-5 — 선글라스 ↔ 시계(잡화 결합은 예외)

"시계/잡화" 처럼 잡화가 결합된 카테고리명은 예외로 허용하고, 순수
"시계" 는 배제한다(다른 대안이 있으면). 다만 11-7의 "미매칭 절대 금지"
가 우선이므로, 정말 다른 후보가 전혀 없을 때는 그것이라도 전달한다
(성별·브랜드처럼 예외 없는 절대규칙은 아님).

### 6. 다중조각(중위) 분해 — `segment_variants`

"모자/잡화"·"모자/기타잡화/신발" 처럼 중위도 하위처럼 슬래시로 여러
단어를 가질 수 있어, 인접 조합까지 전개하는 일반화 함수로 통합했다
(`low_variants` 는 하위호환 별칭).

### 7. `map_categories.py` — DB 연동 · AI 버튼 재활성화

`build_category_db()` 로 실행 시작 시 DB를 1회 구축해 `best_category*`
· `map_one_market` · `_map_once` · `map_one_row` 전체에 `db` 를 전달한다.
요건 C-3 그대로 [AI 자동 매핑 시작하기] 클릭을 재활성화했다 — 그 결과에
로직을 얹지 않고, 실패 시 `clear_market_category` 로 필드를 비우는
안전장치(v2.27.0)로 계속 보호한다.
