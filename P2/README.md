## 확장프로그램은 전용 프로필에 1회 설치 (v2.1.53)

P2 는 평소 쓰는 Chrome 이 아니라 **전용 프로필**(`P2/.chrome-profile`)로 Chrome 을
새로 띄웁니다. Chrome 136 부터 원격 디버깅(`--remote-debugging-port`)이 기본
프로필에서 무시되기 때문에 선택의 여지가 없습니다. 그래서 평소 Chrome 에 더망고
확장이 설치돼 있어도 P2 창에는 적용되지 않습니다.

또 Chrome 137 부터는 정품 Chrome 에서 `--load-extension` 스위치가 제거되어
`P2/extensions/themango-solution` 을 넘겨도 조용히 무시됩니다
(크롬 로그: `--load-extension is not allowed in Google Chrome, ignoring.`).

따라서 **최초 1회만** P2 가 띄운 Chrome 창에서 웹스토어로 확장을 설치해 주세요.
확장이 없으면 P2 가 설치 페이지를 자동으로 띄우고, 수동 로그인 대기와 같은 방식으로
**[Chrome에 추가] 를 누를 때까지 대기했다가 설치가 확인되면 그대로 이어서 진행**합니다
(`EXT_INSTALL_WAIT_SEC` 기본 600초, 보드 [수집 종료] 로 즉시 취소 가능).
P2 를 다시 실행할 필요는 없습니다.
설치 내용은 전용 프로필에 남으므로 다음 실행부터는 대기 없이 지나갑니다.

`--disable-extensions-except` 는 **절대 넣지 않습니다.** "지정 경로 외 전부
비활성화" 라서 위 웹스토어 설치분까지 매 실행 꺼버립니다 — 이것이
"더망고 확장프로그램이 설치되어 있지 않습니다" 배너의 직접 원인이었습니다.

보드 **[수집 종료]** 로 중도 중단 가능(실행로그 화면 보존).  
입력 1번은 행당 제한시간(기본 180초)·확정실패 시 같은 행을 무한 반복하지 않고 다음 입력으로 넘어갑니다.  
2번(이후) 수집 전, 열린 팝업/모달이 **모두 종료될 때까지 대기**한 뒤 스크린샷(`00_overlays_clear`)을 보관하고 진행합니다.  
두 버튼은 **반드시 둘 다** 실행합니다 (다른 버튼임).

1. **[버튼1]** 결과목록 상단 `검색된 상품 모두저장` → 상품저장설정 모달 열림  
2. 검색필터명·저장상품수 입력  
3. **[버튼2]** 모달 하단 파란 `저장하기`(옆 `취소하기`) → 서버 최종 갱신  

버튼2는 취소하기 옆 푸터 쌍으로만 찾고, `모두저장`/`선택상품저장`과 절대 혼동하지 않습니다.  
**저장하기 이후(9~12항)** 순서 고정:  
9) 저장하기 클릭 → 10) 저장 팝업 열림 → 11) **저장 팝업 닫기-확인** → 12) **N건 수집 로그** → 13) 초기화.  
- 검색 팝업(6항)도 닫힘 확인 전에 모두저장으로 가지 않음 (강제닫고 진행 금지)  
- 본문 잔여 「N건이 수집」 문구만으로는 팝업으로 보지 않음  
- `save_awaiting_popup` 중에는 `0. 초기화` 진입 자체 거부  
반응 없으면 **최대 1회 재시도** 후 다음 행.  
9항 클릭 후 반응이 없으면 실행로그에 **[9항 진단]/[9항 원인추정]**으로  
가로채는 요소(오버레이)·미선택 필수값(정책 등)·iframe 여부를 바로 표시합니다.

**중요:** 저장(9~11항) 팝업은 같은 관리자사이트(ADMIN_HOST) 새 창으로 뜨는 경우가 많습니다.  
검색 팝업 판별용 `popups()`는 ADMIN_HOST 창을 제외하므로, 저장 팝업 탐지에는  
반드시 `save_popups()`(ADMIN_HOST 포함)를 사용합니다. 이전에는 이 구분이 없어  
"저장하기를 눌러도 팝업이 전혀 안 뜬다"처럼 보였습니다(실제로는 뜨는데 코드가 못 봄).

**추가 원인:** `save_modal_visible()`(제목·정확텍스트 매치)이 아이콘/공백 변형에  
오탐(false negative)하면, 저장하기를 **클릭 시도조차 하지 않고** 즉시 실패 처리하던  
게이트가 있었습니다. 이제 그 검사가 실패해도 클릭 자체는 계속 시도하고,  
판정 로직도 클릭 함수와 같은 기준(`_find_footer_save_by_cancel_pair`)을 최우선으로 씁니다.

**★가장 유력한 근본원인 (v2.0.45):** 클릭은 되는데 "저장 팝업창 모달" 자체가  
**실제로 열리지 않는** 경우 — Chrome 자체 팝업차단(진짜 Chrome 프로필은 기본 ON).  
클릭이 trusted 여도, 사이트가 저장 AJAX 완료 콜백에서 **비동기로** `window.open()`을  
호출하면 Chrome이 "사용자 제스처 없음"으로 보고 조용히 막아버립니다 — 팝업 창 자체가  
생기지 않으니 코드가 아무리 잘 찾아도 볼 수 없습니다.

- Chrome 실행 인자에 `--disable-popup-blocking` 추가
- **중요:** 이 플래그는 Chrome을 **새로 켤 때만** 적용됩니다. 이전부터 열려 있던  
  Chrome을 계속 재사용 중이면 여전히 막힐 수 있습니다 — **Chrome을 완전히 종료**  
  (작업관리자에서 관련 프로세스까지 확인)한 뒤 다시 실행하세요.
- 클릭 후 새 창이 0개면 실행로그/오류 메세지에 이 원인을 바로 알려줍니다.

## 저장완료 메세지 즉시탐지 (v2.0.50 — 이전 120s/300s 단계적 대기 대체)

- 저장하기(9항) 클릭 후 **120초 무행동 대기·300초 단계적 확인 방식은 폐기**.
- 클릭 직후부터 짧은 간격(200ms)으로 곧바로 확인하며, 망고 메세지
  **"신규상품의 저장이 완료되었습니다"**(또는 기존 'N건이 수집됨' 알림)가
  보이는 **즉시** 10·11·12항을 모두 만족한 것으로 보고 13항(초기화)으로 진행.
- `SAVE_COMPLETE_WAIT_SEC`(60초)은 그래도 메세지가 안 보일 때의 순수
  안전망(무한 대기 방지)일 뿐, 평소엔 훨씬 빠르게 끝납니다.
- 10·11·12항은 신호 확인 즉시 각각 **개별 스크린샷**을 sub 로그에 남깁니다
  (`10_popup_open`/`11_popup_closed`/`12_count_logged`).
- **화면 스크롤 절대 금지** — 입력필드값 입력·버튼 클릭 외에는 화면이 움직이지 않습니다  
  (`scroll_to_product_strip`/`scroll_save_modal_to_footer`/마우스 호버 등 전부 제거).

## 초기화(2항)·검색(6→7→8) 지연 제거 (v2.0.50)

- **상품수집 필드 초기화는 어떤 행이든 항상 "2단계"** — 다음 행이라고 "13"으로
  갈아타지 않습니다(전 버전 버그 수정).
- 2항 초기화 후 3항까지의 고정 대기(≈8초)를 제거 — URL검색 버튼이 실제로
  보일 때까지만 기다리고 그 이상 블라인드로 쉬지 않습니다.
- **(v2.0.51)** 그래도 2→3항 사이에 지연이 남는다면, 코드가 만드는
  블라인드 sleep은 이제 없으므로 실제 페이지 전환·서버응답·렌더링
  시간일 가능성이 큽니다. 다음 실행부터는 sub 로그에
  `[타이밍] domcontentloaded=...s, URL이동/로그인체크=...s,
  URL검색버튼 보일때까지=...s`가 남아 정확히 어느 구간인지 바로
  확인할 수 있습니다.
- **6항(검색팝업 닫힘) 확인 후 7·8항은 단계별 딜레이 없이 즉시 수행** —
  스크린샷용 이미지 대기(`prepare_product_view_for_shot`)를
  `fast=True`로 최소화하고, 7항 모달 확인 폴링 간격도 축소, 꼬리의
  고정 대기(300ms)를 제거해 9항 진입까지 걸리는 시간을 최소화합니다.

## 8항 — 검색필터명·저장상품수 입력 (v2.1.54)

- **검색필터명**에 엑셀의 **`최종 카테고리명`** 을 입력합니다
  (그 열이 없는 옛 엑셀은 `상위 최종 카테고리명` 으로 대체).
- **저장상품수**를 `DEFAULT_SAVE_COUNT`(**50**)로 맞춥니다. 망고 모달 기본값이
  3 이라 손대지 않으면 행당 3개만 저장되기 때문입니다.
- 이후 12항(저장건수 확인)은 모달에 최종적으로 들어간 값을 기대값으로 씁니다.
- 두 필드 모두 최대 4라운드까지 확인·재입력하고, 저장상품수를 넣는 과정에서
  검색필터명이 흔들리면 확정 실패로 잡습니다.

> v2.0.49 의 "저장상품수는 원래 세팅값 그대로 둔다" 요건은
> 2026-08-20 요건("저장상품수 3개 → 50개")으로 대체되었습니다.

## 8항 필드혼동 버그 수정 (v2.0.47~2.0.48)

- `modal_field()`가 넓은 공용 div까지 매치해 **저장상품수 칸에 검색필터명이
  덮어써지던 버그**를 수정 (좁은 조상만 타고 올라가도록 재작성).
- 두 필드가 실제로 같은 엘리먼트로 잡히면 즉시 확정 실패로 조기 검출.
- **(v2.0.48)** 기존에는 필터를 넣고 → 카운트를 넣고 → **필터를 다시
  무조건 재입력**해서, 그 사이 카운트가 이미 맞게 들어가 있어도
  "필터 재입력"이 사이트 JS를 다시 건드려 카운트 값이 덮어써지는
  사고가 있었음. 이제는 **매 라운드 끝에 두 값을 다시 읽어 이미 맞으면
  그 필드는 더 손대지 않고**, 틀린 필드만 다시 채우는 방식으로 바꿔
  불필요한 재입력·덮어쓰기를 없앴다(최대 4라운드, 그래도 안정 안 되면
  명확한 오류로 확정 실패).

## 실행로그 — main/sub 두 그리드 (v2.0.46)

- **main**: 1~13단계 줄만 (그 외 잡다한 로그는 화면에 안 보임).
- **sub**: main에서 선택한 단계(행)에 딸린 추가정보·스크린샷만.
- 프로토콜: `board/log_protocol.py` (`##MAIN##seq##n##msg` / `##SUB##seq##msg` /
  `##SUBSHOT##seq##path##label`) — `RunCtx.step()`/`info()`/`shot()`이 표준출력으로 보냄.

엑셀 헤더: `최종 카테고리명`(없으면 `상위 최종 카테고리명`) | `최종 카테고리 URL주소`
